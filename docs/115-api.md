# 115 网页接口笔记（2026-11 调研）

> 来源：JAV老司机-新 v13.0.0.1、Magnetic_Assistant、115driver、p115client、115-quick-transfer、AList 115 驱动。
> 这些是**网页/客户端同款接口**，不是 115 官方开放平台。接口可能随 115 改版失效，改版时优先检查这里。

## 本项目（0.3.7）当前使用情况

| 用途 | 当前实现 |
|---|---|
| 离线签名 | `GET https://115.com/?ct=offline&ac=space` |
| 添加任务 | 旧版 `POST https://115.com/web/lixian/?ct=lixian&ac=add_task_url`（单个 URL） |
| 任务列表 | 旧版 `task_lists` 第 1~3 页；`2/10/11` 完成，`-1/3/9` 失败 |
| 状态兜底 | `percentDone >= 100` 时用目标目录差异判断完成；任务卡上的「按目录检查」可手动触发 |
| 列目录 | APS `https://aps.115.com/natsort/files.php`，失败回退 `webapi.115.com/files` |
| 路径转 cid | `webapi.115.com/files/getid` |
| 改名 | 逐条 `webapi.115.com/files/edit`；`batch_rename` 已记录但暂未默认启用 |
| 删除 | `webapi.115.com/rb/delete`，20 个/批 |
| 验证码 | 暂未做插件内面板；911 时打开 115 页面手动验证 |

新版 `clouddownload.115.com` / `lixianssp` 接口（支持批量添加、RSA 编码）记录在下方，作为后续兼容和优化方向。

## 1. 登录 / 签名

### 离线签名

```
GET https://115.com/?ct=offline&ac=space&_=<timestamp>
```

- 已登录：返回 JSON，含 `sign`、`time`。
- 未登录：返回 HTML 登录页。

新版网页也使用：

```
GET https://115.com/?ct=clouddownload&ac=space
```

两个都可以试；本项目当前用 `ct=offline`。

### 轻量账号信息（用于登录检查 / 取 uid）

```
GET https://my.115.com/?ct=ajax&ac=nav
```

返回用户信息，可取 `data.uid` / `user_id`。比 `webapi.115.com/files` 轻，适合做登录检查。

## 2. 云下载

### 2.1 旧版网页接口（本项目当前使用）

添加单个任务：

```
POST https://115.com/web/lixian/?ct=lixian&ac=add_task_url
Content-Type: application/x-www-form-urlencoded

url=<magnet 或 ed2k>
uid=<可空>
wp_path_id=<目标目录 cid，可选；根目录可省略>
sign=<离线签名>
time=<签名时间>
```

- 成功：`{"state": true}`
- 重复任务：`errcode = 10008`，可视为成功/重复。
- 风控：`errcode = 911` → “请验证账号”
- 频繁：`590075` → “操作太频繁，请稍候再试”
- 登录失效：`99` / `990001`

任务列表：

```
GET https://115.com/web/lixian/?ct=lixian&ac=task_lists&page=1
```

- `tasks[]` 含 `info_hash`、`name`、`status`、`size`、`percentDone` 等。
- 老司机代码里的状态判断：`2` / `11` = 完成；`-1` / `3` / `9` = 失败；其它为进行中/等待。
- 任务可能翻页；找不到时查 1~3 页。

### 2.2 新版网页/客户端接口（后续可做批量优化）

```
POST https://lixian.115.com/lixianssp/?ac=add_task_url
POST https://lixian.115.com/lixianssp/?ac=add_task_urls
```

- `add_task_urls` 支持一次提交多个 `url[i]`，可显著减少请求数。
- 参数：`ac`、`wp_path_id`、`app_ver`、`uid`、`url[0..n]`。
- 请求体是 RSA + XOR 编码后的 `data=<base64>`，query 带 `t=<timestamp>`。
- 115driver 的 `pkg/crypto/m115` 和 JAV老司机里的 `m115Encode/Decode` 是同一套算法；需要时可移植到 JS。
- 新版任务列表：`GET https://clouddownload.115.com/?ac=task_lists&page=1&page_size=30`，`stat` 语义：`1-9` 失败、`10-11` 完成、`12` 进行中。

### 2.3 115 开放平台（不推荐）

```
POST https://proapi.115.com/open/offline/add_task_urls
GET  https://proapi.115.com/open/offline/get_quota_info
```

需要 `open.115.com` 的开发者 AppID / access_token；官方协议禁止把开发凭证共享给他人，开源工具不能内置公共 AppID。个人自用需自行申请，流程较重。

## 3. 目录 / 文件

### 3.1 列目录（APS 极速接口，优先）

```
GET https://aps.115.com/natsort/files.php
  ?aid=1
  &cid=<目录 id，根目录 0>
  &offset=0
  &limit=500
  &show_dir=1
  &format=json
  &record_open_time=1
  &count_folders=1
  &natsort=1
  &fc_mix=0
```

- `115-quick-transfer` 作者明确：`webapi.115.com/files` 目录接口**极易触发风控**，优先用 APS。
- 响应字段与 webapi 一致：
  - 文件：`fid`（文件 id）、`cid`（父目录 id）、`n`（名称）、`s`（大小，字节）、`pc`（pickcode）
  - 文件夹：`fid` 为空或 `0`，`cid` 是文件夹 id
- 单次最多约 1200 条；结果目录一般远小于这个数。

回退接口：

```
GET https://webapi.115.com/files
  ?aid=1&cid=<cid>&o=user_ptime&asc=0&offset=0&limit=100
  &show_dir=1&type=0&natsort=1&record_open_time=1&format=json
```

### 3.2 路径转目录 id

```
GET https://webapi.115.com/files/getid?path=/电影
```

- 返回 `id`（也可能是 `cid` / `file_id` / `data.id`）。
- **注意**：路径不存在时 115 不一定报错，而是返回 `state:true, id:0`；要自行判断。
- 路径要 URL 编码，例如 `/电影` → `%2F%E7%94%B5%E5%BD%B1`。

### 3.3 新建目录

```
POST https://webapi.115.com/files/add
  cname=<名字>
  pid=<父目录 id，根目录 0>
```

返回 `cid` / `cate_id` / `id` / `data.cid`。

### 3.4 改名

单个（老司机用这个）：

```
POST https://webapi.115.com/files/edit
  fid=<文件或文件夹 id>
  file_name=<新名字>
```

批量（115driver 用这个，**待真实账号验证**）：

```
POST https://webapi.115.com/files/batch_rename
  files_new_name[<fid1>]=<name1>
  files_new_name[<fid2>]=<name2>
  ...
```

- 也兼容单个 `fid` + `file_name`。
- 如果批量接口失败，逐个回退到 `files/edit`。
- 文件名非法字符：`\ / : * ? " < > |`；115 会自动替换，建议客户端先清洗。

### 3.5 删除（进回收站）

```
POST https://webapi.115.com/rb/delete
  fid[0]=<id1>
  fid[1]=<id2>
  ...
  ignore_warn=1
```

- 一次可传多个 `fid[i]`；建议 20~50 个一批，批间 1.5~2 秒。
- 删除进入 115 回收站，可恢复。
- 删除文件夹会连同内容一起进回收站；只对确认是垃圾的目录做。

### 3.6 移动

```
POST https://webapi.115.com/files/move
  fid[0]=<id1>
  fid[1]=<id2>
  pid=<目标目录 id>
  move_proid=
```

可选 `conflict_policy` JSON 处理重名；扁平化/合并时使用。

## 4. 验证码（911）

### 4.1 触发

任意 115 接口返回：

```json
{"state": false, "errno": 911, "error": "请验证账号"}
```

或旧接口的 `errcode: 911`。

处理原则：**立即暂停全部请求，让用户手动验证**；不要自动重试、不要自动破解。

### 4.2 验证码接口（p115client 已确认）

```
GET https://captchaapi.115.com/?ct=index&ac=code&t=all     # 10 个带编号的汉字图
GET https://captchaapi.115.com/?ct=index&ac=code           # 4 个目标汉字图
GET https://captchaapi.115.com/?ac=code&t=sign             # 返回 sign
POST https://webapi.115.com/user/captcha                   # 提交
```

提交参数：

```
code=<4 个数字，对应 10 个汉字的编号，按目标汉字顺序>
sign=<captcha sign>
ac=security_code
type=web
ctype=web
client=web
```

成功返回 `state:true`。这四个汉字由 10 个汉字中选 4 个，用户按顺序点选编号即可；这是**手动**流程，不做 OCR。

### 4.3 兜底

如果验证码不是图片型（滑动/短信），或连续失败 3 次，打开：

```
https://115.com/?tab=offline&mode=wangpan
```

让用户在 115 页面完成验证，然后探测一次 `?ct=offline&ac=space` 确认恢复。

## 5. 风控 / 频率相关错误

| 错误码 | 含义 | 处理 |
|---|---|---|
| `911` | 请验证账号 | 暂停全部，手动验证，冷却 10 分钟 |
| `590075` | 操作太频繁，请稍候再试 | 60s → 5min → 30min 退避 |
| `99` / `990001` | 请重新登录 / 登录超时 | 停止，提示登录 |
| `10008` | 重复任务 | 视为可接受 |
| `20002` | 目录名超过 20 字 | 客户端截断/提示 |
| `20003` | 文件名含非法字符 | 客户端清洗 |
| `20004` | 目录名已存在 | 复用已有目录或改名 |
| `20013` / `20018` / `31003` | 文件/目录不存在 | 跳过并重新扫描 |
| `990001` | 登录超时 | 同 99 |

## 6. 频率建议（经验值，非 115 官方阈值）

| 类别 | 最小间隔 | 每小时上限 |
|---|---|---|
| 推送离线 | 10 秒 | 20 条 |
| 任务轮询 | 5 分钟（可退避到 15 分钟） | 60 次 |
| 目录读取 | 1.5 秒 | 120 次 |
| 删除 | 2 秒/批（20~50 个/批） | 60 次 |
| 改名 | 1.5 秒/条 | 120 次 |
| 全部请求 | 1.2 秒/次 | 300 次 |

115 没有公开阈值；以上是多个项目的保守取值，按实际观察调整。
